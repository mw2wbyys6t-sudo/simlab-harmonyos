# 课程地图（学科 × 学段 × 课程 × 实验）设计

日期：2026-10-07　状态：用户已批准设计，并明确批准本文件与 `content/map/` 的写入
关联：`2026-09-24-simlab-brine-purification-benchmark-design.md`（产品定位与四条不变量）

## 1. 这份东西是什么，不是什么

**是**：一张可查的施工清单。每个节点是一个真实开过的实验，标注它需要什么器材、考什么知识点、
以及**当前这个应用能不能做**。

**不是**：仿真本身。加一条记录不等于应用能做这个实验。地图与实现之间隔着世界模型、
判分细则和渲染器三件事，那三件事各自要单独论证。

选这个形态的四个决定（用户 2026-10-07）：用途＝先建地图按图施工；范围＝理工基础四大件；
粒度＝实验为主、知识点当标签；形态＝仓库数据 + 应用内只读浏览页。

## 2. 现状（当场量出来的，不是印象）

- `Subject` 枚举 7 个值，只有 3 个有内容：力学 2 个场景、电学 2 个场景、化学
  （量取训练 + 实验台 + 28 条反应 + 粗盐提纯链路）。生物/地理/数学可视化/仪器是空枚举。
- 分类字段 `gradeBand` 是**自由字符串**（`'初中物理 · 九年级'`、`'高中物理 · 选择性必修一'`），
  没有任何结构。所以"按学科及年级分门别类"是从零开始，不是整理已有内容。
- 现有 7 个可运行经验散在页面里（`MeasurePage` 自己造 meta，`MechanicsScenes` 等各自注册）。

## 3. 数据模型

`entry/src/main/ets/content/map/CurriculumTypes.ets`

```
enum MapSubject   { PHYSICS, CHEMISTRY, BIOLOGY, ELECTRONICS }   // 与 Subject 分开:那是渲染/判分用的
enum SchoolStage  { JUNIOR, SENIOR, UNIVERSITY }
enum Feasibility  { RUNNABLE, NEEDS_MODEL, NEEDS_RENDERER, NEEDS_REAL_GEARS }
class ExperimentEntry { id, title, subject, stage, course, term, minutes,
                        apparatus[], principle, dataHandling, knowledge[],
                        feasibility, source, verified }
```

四档 `Feasibility` 的区别不是工作量而是**做法不同**：`NEEDS_MODEL` 补物理/化学模型；
`NEEDS_RENDERER` 要先补画法（波动与干涉、光谱、三维结构、显微视野）；
`NEEDS_REAL_GEARS` 表示这个实验的教学目的本身就长在真实仪器的手感、调节步骤或实物观察上，
**做成仿真就是假实验**，应当明确排除而不是排进工期。

`verified` 由 `source` 推导（以 `未核实:` 开头即为假），不是手写字段——
否则一定会长出"出处写着未核实、verified 却是 true"这种自相矛盾的数据。

## 4. 文件切分

按学科切，不塞一个大表：400 条 × 每条 8–15 行 ≈ 5000–7000 行，单文件到这个尺寸
就是"它在做太多件事"的信号（本项目先例：`LathePainter` 456 行时已经开始难改）。

```
content/map/
  CurriculumTypes.ets        数据模型 + 枚举 + makeEntry
  UniversityPhysics.ets      大学物理实验(力学与热学/电磁学/光学/近代物理)
  UniversityChemistry.ets    无机及分析化学实验 + 有机化学实验
  UniversityBiology.ets      普通生物学实验
  UniversityElectronics.ets  电工技术/模拟电子/数字电子实验
  SchoolPhysics.ets          初中与高中物理(现有 4 个场景迁进来)     ← P3
  SchoolChemistry.ets        初中与高中化学(现有量取与实验台迁进来)  ← P3
  MapValidator.ets           纯逻辑校验,离线断言直接跑
  CurriculumIndex.ets        汇总与查询口(按学科/学段/学期/课程/知识点取用)
```

**不用 JSON/rawfile**：ArkTS 常量表过编译期类型检查，rawfile 只在运行时炸；
且 `tools/physics-check/check.mjs` 能直接 import 前者跑校验（`ChemistryLibrary` 就是这个模式）。
代价是改目录要重新构建——地图是低频改动，接受。

## 5. 出处规则（本设计的核心约束，不是附注）

- 每条 `source` 不许为空。
- 检索到的（能指到学校实验中心页面、教材目录或课标文件）→ 写出处，`verified = true`。
- 凭通用知识写的 → `source` 必须以 `未核实:` 开头，`verified = false`。
- **出处只保证"这个实验确实开课"**。`principle` / `apparatus` / `dataHandling` 三栏是编写者
  按该实验的标准做法概括的，不是从来源页逐字抄的——这一层区别写进每个数据文件的头部注释，
  免得地图看起来比它实际的确切程度更高。

已核实来源（2026-10-07 检索）：

| 来源 | 覆盖 | 拿到什么 |
|---|---|---|
| 云南大学实验中心·物理实验项目列表 `lyxywlsn.lyun.edu.cn/zxgk/xmlb.htm` | 力学/热学/电磁/光学/近代/中学物理/演示/电子工艺 | 约 120 条分类实验名 |
| 南京大学物理实验中心·基础物理实验 `phylab.nju.edu.cn/kcsz/jcwlsy/index.html` | 大学物理实验(一) | 16 条实验名 |

**化学、生物、电子第一轮没有可核查来源**：广西师大化学实验中心页抓取失败（fetch failed）、
百度百科《普通生物学实验》403、一份分析化学教学大纲的抓取被安全策略拦下。
这三份文件第一轮**全部条目按 `未核实:` 标注**，等补到来源再逐条升级（P2）。这一条不许含糊过去。

## 6. 校验（`MapValidator`）与测试

纯逻辑，进 `check.mjs`（当前 2102 条断言）：

1. `id` 全局唯一，且匹配 `^(phy|chem|bio|ele)-(u|jr|sr)-\d{3}$`。
2. 必填非空：`title` / `course` / `term` / `source`；`apparatus` 与 `knowledge` 至少各 1 项。
3. 三个枚举取值合法；`minutes >= 0`。
4. `verified` 等于 `source.indexOf('未核实:') !== 0`。
5. `stage` 与 id 中的学段码一致；`subject` 与 id 中的学科码一致。
6. 查询口给出的分类计数与逐条统计一致（防查询口自己漏项）。

第 4、5 条是**判别性断言**：把 `verified` 改成手写常量、或把 id 与学科对调，都必须变红。
按本项目纪律，落地后要跑变异确认——假断言比没有断言更糟（spec 8.19、8.21、8.24 三次同类翻车）。

## 7. 浏览页（应用内只读）

- 入口：首页新增「课程地图」卡片，走现有 `routeMap` 的 `if / else if` 单链
  （平级 `if` 只渲染第一个，是已记录的静默陷阱）。
- 一级：学科筛选（复用现有 chip 组件）；二级：学段 → 学期/册次分组（复用历史页分组的路子，
  含"组首才显示分组标题"那条已修过的坑）；三级：实验详情。
- 详情显示：名称、课程与学期、器材、原理、数据处理要求、知识点标签、可行性状态、出处，
  以及一个诚实的标记：**"这个实验现在能不能做"**。
- 不做搜索、不做编辑、不做学习进度记录（那些各自要独立论证）。

## 8. 明确不做

- 不做"实验即数据"的运行时管线（新增实验不写代码）——那要重构现有 Runner/细则/页面结构，
  是另一个量级的决定。
- 不改现有 7 个可运行实验的实现，只做迁移登记。
- 不建独立知识点表（知识点只作为实验的标签存在，索引从标签汇总）。
- `NEEDS_REAL_GEARS` 的条目不进任何工期表，它们存在的意义就是**说明为什么不做**。

## 12. 2026-10-08 续:元素周期表,以及实验台开始显示方程式

用户补三条化学要求:要有元素周期表、要有反应方程式、**做实验时屏幕上要出现方程式**。
先量现状再动手,结果三件事落在三个不同地方:

- **周期表此前不存在**。`Formula.ets` 里的 `AtomicMassTable` 只有 32 种元素的**取整**原子量,
  是给式量计算用的工作表,不是元素知识。
- **反应方程式已有 28 条**,且 `ReactionSpec` 字段完整(条件、`benchReady`、现象、
  离子方程式、安全提示),`ReactionValidator` 做元素/质量/电荷三重守恒 —— 不用重造。
- **"做实验时出现方程式"是一处接线缺口,不是新功能**:`BenchEngine.react()` 本来就在跑反应、
  发 `BenchEvent`(带 `phenomena`),`ReactionText.equation(spec)` 本来就能拼带条件与可逆箭头的式子 ——
  但 `BenchPage` 的事件日志只打现象,不打式子。

**新增 `PeriodicTable.ets`:118 种全收**(含镧系系与人造超重元素),字段为
序号 / 符号 / 中文名 / 相对原子质量 / 周期 / 族(长式 1–18) / 区 / 常温状态 / 金属性 / 常见化合价 / 提示。
刻意**没有**收录电子排布 —— 那是另一件要单独核对的事,半列留空比填错好。
两处如实交代在文件头:超重元素质量数取最长寿命同位素;**104–118 的中文名按中国化学会 2017 年命名,
未逐字核对**,且这些字多在 CJK 扩展区,浏览页必须做字体回退,不能假定渲染得出来。

**最有价值的一条断言是两张原子量表互校**:周期表的 `mass` 与 `Formula.relativeMass(符号)`
允许差 0.6(式量表按整数取整,Cl 取 35.5),超过即说明有一处录错元素或点错小数点。
另有一条结构不变量:**每周期元素数必须等于 2/8/8/18/18/32/32** —— 把任何一个元素填错周期都会红。
还有一条抓错得很快的:常温气态恰好是那 11 种、液态恰好只有溴与汞。

**方程式改为随事件走**:`BenchEvent` 新增 `equation` 与 `ionicEquation`,由 `BenchEngine.run()`
在成事那一刻填,`BenchPage` 在标题之后、现象之前打印。
不让页面拿 `reactionId` 反查 —— 那会把"这是哪条反应"的判定摊到视图层,违反不变量 I3。

**这一轮又差点留下假断言。** 我先写的那组只测 `ReactionText.equation(spec)` 拼得对不对,
**把引擎里 `event.equation = ...` 那行删掉,2213 条照样全绿** —— 式子算对了但没送进事件,
屏幕上依旧什么都不显示。补了一条真正走通链路的断言:遍历可台架反应、装药、`react()`、
要求**跑起来的事件其 `equation` 等于 `ReactionText.equation(spec)`**;
并且同时断言"确实有 ≥3 条反应跑起来了",否则前半句又是一句空话。
变异复测:删掉赋值 → 1 项红。

断言 **2213 → 2215**(周期表那组 2210→2213 时我自己写错两条:气态清单的字典序、
以及给反应库元素数拍了个 20 的门槛 —— 实测只有 16 种,这本身是反应库太窄的信号)。
构建绿;`BenchEngine` / `BenchPage` 编译缓存命中 3(可达,已过 ArkTS);
`PeriodicTable` 与三张知识表仍是 0 —— 那笔债没变,做浏览页时一起还。

### 14.3 化合价必须带符号,这条放在数据层

设备上看到氢的价态写成 `-1、1`。化学里 `+2` 与 `2` 不是一个意思 —— 裸数字会被读成「有 2 个价态」。

外加「118 条价态串每一段都匹配 `^[+-]\d+$`,空数组一律出「无稳定化合价」」。
变异验证:把 `'+' + String(v)` 改成 `String(v)`,三条断言同时红。

### 14.4 一条被实测推翻的说法:两张表其实不互查

`KnowledgeTypes.ets` 的文件头原先写着「实验那一份不动,两边靠 `knowledge` 标签与 `kp` 编号互查」。
**这句话是假的**,而且假得可以量化。跑了一遍现状:

- 224 条实验共 910 个 `knowledge` 标签,能**精确**对上某条知识点标题的:**1 个**(0.1%)。
- 放宽到子串匹配(标题/章名/陈述 任一含标签或反之):去重后 817 个标签里
  零命中 668、单命中 107、多命中 42 —— 覆盖率 18%,而且「波长→7 条」这类多命中是假阳性。

也就是说:自动建链建不出来,手工建链是 910 次判断。而**现在没有任何功能需要这条链** ——
浏览页是只读的,判分不查知识点,首页列表也不按知识点分组。
所以这一节的决定是:**不假装链接**,把文件头改成实话,浏览页不做「知识点 → 实验」跳转,
链接这件事登记成 #51,等到真要做「这个知识点没实验覆盖」那张报表时再按 `kn-` 编号显式建。
断言里也**不**钉住 0.1% 这个数 —— 钉住一个坏数字只会在有人改善它时红,那是在奖励不做。

## 15. 「现在能打开 11 个」是假的:可行性重判

地图进应用之后第一件事不是加内容,是把最显眼的那个数查了一遍。

**怎么暴露的。** §14 的表里电子写着 8 条 `RUNNABLE`,依据是代理读了 `physics/circuit/`
之后判断「现有 MNA 求解器够用」。这句话本身没错,错在它答的不是 `RUNNABLE` 定义的那个问题。
`Feasibility.RUNNABLE` 的注释写的是「应用里已经真的能做(有世界模型 + 细则 + 渲染)」,
而 `ExperimentRegistry` 一共只注册了四条:弹簧振子、含摩擦的斜面、串联电路、并联电路。
顺手又核了化学的 `chem-u-021 粗食盐的提纯` —— 它要的是溶解→过滤→除杂→**蒸发浓缩→结晶烘干**,
应用里 `Filtration` 只被 `BrineScenario` 用着,蒸发与结晶连模型都没有。

**为什么原来的断言没拦住。** 那一版写的是 `assertTrue('地图里确实已有可打开的实验', runnable.length >= 5)`。
下限对虚报是盲的:11 条比 5 大,过。**只有等号能拦。** 换成:

```
地图自称可打开的集合 === 应用真装了的集合  // ['chem-u-004', 'phy-u-014']
```

红的时候它把两边都列出来(`地图 [chem-u-004,chem-u-021,ele-u-001,…] vs 应用 [chem-u-004,phy-u-014]`),
这一条改完才绿。清单在断言里注明跟着 `Index.ets` 的 `routeMap` 与注册表走 ——
往地图里加 `RUNNABLE` 之前,先要能在那两处指到一个真点得开的实验。

**没有把这些条目降成 `NEEDS_MODEL`,因为那会丢掉真正的信息。** 电子这 8 条与「缺模型」那批
不是同一种活:前者只要再写一条 `CircuitSpec` 场景加它的细则,引擎与画法都不动;
后者要补物理。所以 `Feasibility` 加了第五档 `NEEDS_SCENE`(待补场景),
`MapValidator` 的取值表、`MapPage.badgeOf` 同步跟上,并加一条
`countByFeasibility(exps, NEEDS_SCENE) === 8` —— 新枚举值没有数据在用就是死代码,这条同时守住
「最低成本的施工面」别被误降级。

**改完的实际读数**(设备 `dumpLayout` 逐科核过):

| 学科 | 实验条数 | 现在能打开 | 出处未核实 |
|---|---|---|---|
| 物理 | 75 | 1 | 0 |
| 化学 | 59 | 1 | 59 |
| 生物 | 41 | 0 | 41 |
| 电子 | 49 | 0(8 条待补场景) | 49 |

全应用 `RUNNABLE` 从 11 降到 2。这个数字变难看了,而它变难看正是这张地图存在的理由 ——
「还剩什么没做」如果答成「已经做了 11 个」,按图施工就无从谈起。

正好落在 1256 = 屏幕边,`dumpLayout` 量出来才发现。给 `menuBar()` 那行 Row 补了

## 17. 按图施工第一发:`ele-u-003 基尔霍夫定律的验证` 从「待补场景」变成点得开的实验

### 17.1 为什么挑这条

17 条 `NEEDS_SCENE` 里,物理那 9 条代理自己都标了保留意见(打点计时器的"用刻度尺估读点迹"属实物、
平抛假定 2D 内核支持无接触抛体但没逐行读 `World2D`)。电子这批的引擎判据是代理读过
`CircuitModel.ets`/`CircuitRunner.ets` 得出的,而我又自己核了一遍元件集合:
两节点三支路、两个直流电压源、三只电流表 —— 全在七种元件里,`solve()` 的电源循环本来就支持多源。
所以挑 `ele-u-003`:引擎适配最确定,且它教的"参考方向"是电工课第一次真正的抽象。

顺带否掉了一个看起来更划算的选择:`phy-jr-017 探究电流与电压、电阻的关系` 要画 I–1/R 图,
而 `ChartDef.xKey` 只能取一个**观测量**,1/R 不是观测量 —— 那是引擎缺口,不是"只差一条场景"。

### 17.2 先红后绿,以及两条红的是我自己的测试

场景按 `n0-[src1]->n2-[r1]->n3-[a1]->n1` 这类拓扑搭,三只电流表统一取 `nodeB = 节点 A`,
于是 `SIGNED_I > 0` 就是流入节点 A。断言分三层:

- **能手算的工况**:`E₁=E₂=6 V、R₁=R₃=10 Ω、R₂=20 Ω` ⇒ 节点 A 电位 4.8 V、源支路各 0.12 A、
  中支路 0.24 A。第二个工况 `6/3 V、10/30/20 Ω` ⇒ `45 = 11V`,右支路算出 **−0.0545 A**,
  负号正是"电源被充电"这一层教学内容。
- **12 组参数扫掠**:节点 A 的三支路代数和必须为零。单点会被对称性掩盖。
- **退化工况**:把中支路拉到 1e7 Ω,左右两支路应等值反号。

两条断言第一次跑就红,**红的是我的期望值,不是代码**:
① 我原本加了一条 KVL 断言(沿回路把各段 `U:` 相加),它测不出任何东西 ——
绕电位差一圈求和是恒等式,而 `U:` 观测量取绝对值,某条支路一反向它必然不为零。删掉,
换成"E₂ 从 +9 V 反接到 −9 V,a₃ 必须穿零变号"这条能判方向的。
② 退化工况我给了 1e-9 的容差,实际闭合差 3e-7 —— 那是 1e7 Ω 中支路的**真实漏流**,
不是求解器误差。容差改成 1e-6,并补一条"漏流必须存在且约等于 V_A/1e7":
写成零反而说明那条支路断了。

### 17.3 一个仪器自身的错:`electrical()` 崩溃会吞掉同批所有断言

变异验证(把 `meta.id` 改名)时,测试不是变红而是抛 `TypeError` 直接终止进程 ——
于是**那一次运行里其他几百条断言的结果一起丢了**,看着像"红了一条",实际是"什么都没测"。
给 `electrical()` 加了具名失败 + 返回读数全 NaN 的桩:NaN 会让每条数值断言都红
(扫掠那条本来就显式判 `!Number.isFinite`,不会假绿)。

变异结果:反接 A₁ → 8 项红;把 A₃ 从节点 A 挪到底轨 → 12 项红;R₂ 接错节点 → 5 项红;
改场景名 → 具名失败且注册表闭合断言同时红。还原后全绿。

### 17.4 顺带修掉一处五个实验共有的渲染缺陷

新实验的图线第一次把**带负号的纵轴读数**(`−0.240`)和**三位数的横轴读数**(`715`)同时摆出来,
于是 `SeriesChart` 里三处坐标轴碰撞全部现形:旋转的 `I / A` 压在 `−0.060` 上、
`t / s` 贴着中间那个刻度、图例压在右边框上。根因是左边界按字号固定成 `fs*3.6`,
而刻度字符串宽度随读数位数与负号变化 —— 前四个实验的读数恰好都不带负号,所以从没暴露。
改成先 `measureText` 量最宽刻度再定左边界,底部按两行留满。这条修的是共用绘制器,五个实验都受益。

### 17.5 地图改口与一条不许偷偷抹掉的限制

`ele-u-003` 从 `NEEDS_SCENE` 改判 `RUNNABLE`:待补场景 17 → **16**,
`SHIPPED_RUNNABLE` 6 → **7**,注册表场景 4 → **5**。

否则改个场景名就能让地图凭空多出一条可打开的实验。

**没实现的那一项写在表里而不是改掉要求**:这条实验的 `dataHandling` 还有一句
"把电流表、电压表内阻贡献的误差分量单独估出来"。场景里我**故意没并电压表**
(每条元件的端电压求解器直接给,再并一只 1e7 Ω 只会添 1e-6 量级的扰动),
所以"电压表内阻"这半在应用里读不出来,电流表的 1e-4 Ω 在。
那一栏描述的是课程实验该做什么,不跟着应用缩水 —— 限制记在表头注释里。

设备实测:`0.1200 A / −0.2400 A / 0.1200 A`、节点 A 电位 `4.800 V`、
`R₁/R₂/R₃ 两端电压 1.200/4.800/1.200 V`,与断言里的解析解逐位一致。

## 18. 第二发:`ele-u-007 负载获得最大功率的条件`

接着 §17 的路子,又清掉一条 `NEEDS_SCENE`。挑它的理由:它是 `RHEOSTAT` 这个元件**第一次**被场景用上 ——
`CircuitRunner` 第 309 行有它的绘制分支,但六个场景里没有一个用过,属于"能力早就有、没人接"。
而这条实验的全部内容就是"扫一个量找极大值",非变阻器不可。

### 18.1 判据是形状,不是单点

`E=6 V、R₀=10 Ω` 时 `P(R_L) = E²R_L/(R₀+R_L)²`,极大值在 `R_L=R₀`、`P_max = E²/4R₀ = 0.9 W`、
此时效率恰 50%。断言分三组:

- **两侧同值**:R₀/2 与 2R₀ 都得给出 0.8 W。只钉峰值那一点,把曲线写成"恒等于 0.9"也能过。
- **扫掠 argmax**:1..100 Ω 逐步扫,峰值位置必须**正好**是 10;再把内阻换成 40 Ω 扫一遍,
  峰值必须跟着搬到 40 —— 这条专抓"把 R₀ 写死成常数"。
- **单调形状**:短路侧 `P(0.5) < P(2) < P(6)`、开路侧 `P(14) > P(30) > P(120)`。

外加效率与功率的矛盾:`η` 随 `R_L` 单调上升、`η(峰值)=0.5`、`η(100)>0.9 而 P(100)<0.9`。
这条是"最大输出功率 ≠ 最高效率"这个教学点的机器版 —— 若把 `P:` 或 `U:` 的符号弄错,
两者会同时取极值,断言立刻红。

### 18.2 两处红的是我写的期望值

1. **容差 1e-9 太严**:实测 `P_max = 0.899991`。差在回路里串着的电流表有 1e-4 Ω,
   总电阻从 20 Ω 变成 20.0001 Ω。这是场景里的真实元件,不是求解器不精确 ——
   要钉到 1e-9 就得把电流表去掉,而"电表有内阻"正是 `ele-u-006` 要教的东西。容差改 1e-4 并写明原因。
2. **"两端远小于峰值"我写成了 `< 0.1`**:实际 `R_L=0.5 Ω` 时 `P=0.163 W`,数是对的、期望是错的。
   换成两侧单调形状那两条。

顺带一个自己踩的坑值得记:**第一次跑变异验证时两个变异都没生效** —— sed 模式写成
`'RHEOSTAT', 'rL', ...`,漏了 `ComponentKind.` 前缀,于是文件根本没被改到,
harness 自然全绿。那"全绿"看着像"断言抓不住",实际是"什么都没改"。
重做时先 `grep -c` 确认改动真的落进文件,再看红。**变异验证必须验"变异发生了"**,
不只验"断言红了"。这次重做后:写死 R_L → 9 项红;R₀ 接错节点 → 16 项红。

### 18.3 一处文字缺陷

画布标签写成了 `R_L` —— 下划线是代码痕迹,和同页其他记法(`R₀`、`E₁`、`A`)不是一套。
改成 `RL`(画布标签、参数名、任务文案)。剩下三处 `R_L` 在源码注释里,不上屏,不改。
