# 学生填数入口(#61)设计 —— 让数据处理类判据第一次能被判

日期：2026-10-16　状态：设计逐节经用户确认（范围、判到哪一步、何时判、可抄性、两条场景的 procedure、分值与例外）
关联：`2026-09-24-simlab-brine-purification-benchmark-design.md`（四条不变量，尤其"判定读事实"）、
`2026-10-07-curriculum-map-design.md`（覆盖度口径）
对应工单：#61 学生填数入口缺失：数据处理类判据判不出来

## 1. 这份东西是什么，不是什么

**是**：一条通道。学生把自己**处理**出来的数交进应用，应用把它与该数据按正确流程应有的结果比对，
判分读的是比对结果。首批接两条场景：`tape-cart`（phy-sr-003 逐差法）与
`projectile-frame`（phy-sr-007 由 y/x² 反求 g）。

**不是**：一个"答题页面"或作业系统。不存账号、不批改文字、不做题库。
也**不是**把面板上已有的数让学生抄一遍再判 —— 那是判眼手协调，见 §3 第三条决定。

## 2. 现状（当场量出来的，不是印象）

- **全工程没有一处 `TextInput`**（`grep -rln "TextInput(" entry/src/main/ets/` 为空）。学生没有任何
  把信息交回应用的通道。
- **`meta.tasks` 在应用里根本不渲染**：唯一的读者是 `tools/physics-check/check.mjs:709`
  （把任务文本喂进半角/黑名单文案闸门）。每条场景声明的 1–2 个任务，屏幕上看不见。
- `TaskDef` 已经有 `expected`/`tolerance` 两个字段（`model/ExperimentTypes.ets:85-91`），
  但没有任何代码消费它们 —— 这条通道早就想好了接口，只是没人实现。
- `FactSheet`（`model/FactSheet.ets`）的注释钉着一条不变量：**"所有值都必须由世界层与账本层在
  操作过程中算出"**，并明确拒绝"学生想做什么"这类意图字段。本设计要开的就是这个例外（§7）。
- `SessionRecord.facts` 是 `FactEntry[]` 数组（`model/SessionRecord.ets:38`），
  所以学生填的数只要进 FactSheet 就自动落盘，历史回看那一层不用改。
- 两条目标场景的细则各是 4×25 分（`bench/RubricTape.ets:32-43`、`bench/RubricProjectile.ets`），
  两份都被离线断言与设备探针验证过"认真做完 = 得分 100"。
- **sr-007 现在量不到自己的点**：面板只有 `pjCardDistance`（当前那一格）与 `pjRatioErr`（离散度），
  描下的每个点的 y 没有任何出口。不补这个，"由 y/x² 求 g"就是让他算一个拿不到的数。
- 设备侧可以真打字：`uitest uiInput inputText <x> <y> <text>` 在这台模拟器上存在（实测 `uitest uiInput help`）。
  验收链不会断在"输入框自动化不了"上。

## 3. 四个决定（用户 2026-10-16 逐条选定）

1. **范围**：数字栏 + 把已声明的任务渲染出来。不是只加输入框（那会让任务继续人间蒸发），
   也不做自由文本判分（关键词判分天然误判，与"宁漏不误"冲突）。
2. **判到哪一步**：偏差 + 错法点名。runner 除了正确流程的结果，还算几种典型错法的答案，
   命中哪一种就在判词里点名哪一种。
3. **何时判**：只在交卷时判。输入时不回显任何对错 —— 边填边试会把"算"变成"猜"，二分就能逼近到满分。
4. **可抄性**：sr-003 不撤读数，改成填**中间量**（逐差法的分子与分母里 T² 的倍数）。
   面板上明晃晃挂着"加速度 a"，让他填 a 就是抄数。

## 4. 数据流

```
meta.submissions ─┐
                  ├─→ ExperimentPage 渲染「要交的结论」：任务文本 + 它挂的填空
学生键入 ─────────
        │ runner.setAnswer(key, value)
        ▼
   ProjectileRunner / TapeCartRunner 的 collectFacts
        │  调用场景的纯函数 procedure(纸带段长 / 描点坐标)
        ▼
   AnswerCheck.match(学生值, correct, fingerprints[], tol)
        │  写事实：ans.<key>、<key>True、<key>Outcome、<key>WrongKind
        ▼
   Judgment（不改动）：一条判据读 <key>Outcome，GT 0 扣分
```

### 4.1 声明

`model/ExperimentTypes.ets` 新增：

```
class SubmissionDef {
  key: string          // 'tapeNumerator'
  taskKey: string      // 挂在哪条任务下：'tape-a-by-difference'
  label: string        // '逐差法的分子（后三段之和 减 前三段之和）'
  unit: string         // 'mm'；空串表示无量纲
  precision: number    // 输入框与判词里的位数
}
```

`SceneBuilders.submission(key, taskKey, label, unit, precision)`，与既有 `action()`/`observable()` 同形。
`IExperimentRunner` 加 `setAnswer(key: string, value: number): void`；默认实现（`Physics2DRunner`）
存进一张 `answers: Map<string, number>` 并暴露 `answer(key)`，场景 runner 不必各自实现。

### 4.2 procedure 是纯函数

每场景一个文件，输入只是数据、输出只是数，不碰 runner、不碰 ArkUI：

```
physics/TapeChunkProcedure.ets
  numerator(segMm: number[]): number            // Σ后半 − Σ前半；切不出两半 → NaN
  denFactor(segMm: number[]): number            // h²
  fingerprints(segMm: number[]): Fingerprint[]  // 见 §5
physics/ProjectileGProcedure.ets
  gFromPoint(yMm, xMm, v0): number
  segmentRatio(yMm[]): number
  fingerprints(...): Fingerprint[]
```

好处是这一层能脱离设备逐条断言（§9），而"数据处理对不对"恰恰是全工程最该被单测的东西。

### 4.3 比对与结果码

`physics/AnswerCheck.ets`（共用，纯函数）：

```
class AnswerOutcome {
  code: number   // 0 算对 / 1 算错（含命中错法）/ 2 没交
  relErr: number // 相对偏差 %
  wrongKind: number // 命中的指纹序号，0 = 没命中
}
match(answer, correct, fingerprints[], tol): AnswerOutcome | null
```

匹配顺序**写死**：先比 `correct`（|relErr| ≤ tol 判 0），没中再逐个比指纹（≤0.5% 记 wrongKind，code=1），
都没中也只记 code=1。`answer` 为 NaN（没填）→ code=2。

分工要说清（2026-10-16 实施时定稿，取代早先"由 runner 决定调不调用"的写法）：
**边界收在 `match` 一处** —— `correct` 非有限**或为 0** 时返回 `null`，调用方据此一个事实都不写。
理由：这条界线若放在各 runner 里"自己记得先判一下"，就有 N 处会忘；放在一处，忘的机会只有一次。
`null`（这题没出）与 `code=2`（没交）必须是两个可区分的出口 —— §7 那处破例全靠它们不混。

`correct === 0` 也算"出不来"是刻意的：相对误差在 0 处没有定义，为它另开一条"0 附近算对"的绝对误差
带宽是新口径，不属于这条通道。落到 sr-003 上：μ ≥ tanθ 时小车不动、纸带全是 0 mm 段，此时
`tape-crowded-start`（最短段 < 2 mm）已经在为这条废纸带扣分，数据判据再扣一次就是重复惩罚。

### 4.4 事实键（一次定清，避免各处自造名字）

以 `tapeNumerator` 为例，`collectFacts` 写这四个键：

| 键 | 含义 |
| --- | --- |
| `ans.tapeNumerator` | 学生填的原话（唯一允许来自输入的键） |
| `tapeNumeratorTrue` | 该纸带按正确流程的应有值 |
| `tapeNumeratorOutcome` | 0 算对 / 1 算错 / 2 没交 —— **判据读这个** |
| `tapeNumeratorWrongKind` | 命中的指纹序号，0 表示没命中 —— 只进判词 |

`tapeDenFactor`、`pjG`、`pjSegRatio` 同形。`ans.` 前缀的键**不进任何判据**（§7 红线）。

## 5. sr-003 的规格：逐差法两个填空

一条任务挂**两个**填空，因为逐差法会错在两处，只问分子就看不见分母错。

**填空 1 `tapeNumerator`：分子 = 后 h 段之和 减 前 h 段之和（mm），tol 3%**
**填空 2 `tapeDenFactor`：分母里 T² 的倍数（无量纲整数），精确相等**

样例纸带（a=2 m/s²、T=0.1 s、n=6 段、h=3）：s = 50, 70, 90, 110, 130, 150 mm

| 指纹 | 表达式 | 分子得数 | 与正确值差 |
| --- | --- | --- | --- |
| **正确** | (s₄+s₅+s₆)−(s₁+s₂+s₃) | **180 mm** | — |
| F1 只吃首尾 | s₆−s₁ | 100 mm | 44% |
| F2 相邻逐段平均 | (s₆−s₁)/(n−1) | 20 mm | 89% |
| F3 相邻配对 | (s₂−s₁)+(s₄−s₃)+(s₆−s₅) | 60 mm | 67% |
| F4 单位错 | ×10³ 或 ×10⁻³ | 180000 / 0.18 | 10³ 倍 |

分母倍数：正确 `h²=9`；D1=1（漏乘段数平方）、D2=3（只乘 h）、D3=36（拿总段数平方）。

**边界**：`n < 4` 切不出前后两半时，两个填空的 Outcome 事实**一律不写**（判据不响、不扣分）——
这是"这题没出"，与"没交"是两件事（§7 第三条）。

## 6. sr-007 的规格：先补数据出口，再两个填空

**前提改动**：描下的每个点在它右下方标出 `y=112.5`（世界快照的 `LabelShape`，
不新增组件、不占面板行）。x 不标 —— 它就是卡片那一格，面板已有。
标"量到的读数"是给数据，`y/x²` 与 `g` 仍要他自己推。

**填空 1 `pjG`：由你描的点反求的 g（m/s²），tol 3%**
取第 2 格的点（x=0.30 m、v0²=3.92）：

| 指纹 | 表达式 | 得数 | 与 9.8 差 |
| --- | --- | --- | --- |
| **正确** | g = 2·(y/x²)·v0² | **9.80** | — |
| G1 漏乘 2 | g = (y/x²)·v0² | 4.90 | 50% |
| G2 把 x 当时间 | g = 2y/x² | 2.50 | 74% |
| G3 用了板角坐标 | y 从板底量起 | 186 | 19 倍 |
| G4 单位错 | ×10³ / ×10⁻³ | 9800 / 0.0098 | 10³ |

G3 与既有判据 `pj-origin-late` 讲的是同一件事的两头：一条说他**手上**没定基准，
一条说他**算的时候**又用回没基准的数。两条判词各说各的，不互相顶替。

**填空 2 `pjSegRatio`：竖直方向第二段与第一段位移之比（无量纲），tol 3%**

| 指纹 | 得数 | 差 |
| --- | --- | --- |
| **正确**（相邻段之差，从抛出点数起 1:3:5:7） | **3.00** | — |
| V1 拿两点总位移之比 y₂/y₁ | 4.00 | 33% |
| V2 以为每段翻倍 | 2.00 | 33% |

V1 正是这条实验最经典的混淆：**"y 与 x² 成正比"不等于"相邻段之比是 2"**。

**边界**（2026-10-18 按扫描结果定稿，取代早先"未定原点也要出题、由 G3 点名"的写法）：
描点数 < 3 时凑不出两段，`pjSegRatio` 不写事实；**未定原点时两格都不出题**。
理由：把板角基准那个 y 当成 G3 指纹去点名，实测在 slot 2/card 1（差 2.77%）与 slot 4/card 3（差 2.24%）
会撞进 3% 判分容差里 —— 那条指纹因此被删（宁可点不出名，也不指认一个没犯的错）。
指纹一删，"未定原点时照样出题"就只剩一个坏处：拿板角标签算出 9.53 的人会被判"算对了"。
所以这一格改成"基准没定 = 这道题还没出"，错误由 `pj-origin-late` 那一条独立承担 —— 它本来就是讲这个的。
留下的空洞如实钉成断言、写进细则头，不假装判得到。

## 7. 判分、分值，以及一处显式破例

**每个填空只挂一条判据**，读 `<key>Outcome`，`GT 0` 扣分。"没交"与"算错"共用一条判据，
判词靠 `<key>WrongKind` 与 Outcome 的枚举文案分别说话。`Judgment` 一行不改。

**FactLabels 加枚举标签表**：值→文案。它现在已经有 `boolean → 是/否` 这个特例
（`model/FactLabels.ets:140-142`），把 0/1/2→"算对了 / 与应有值差 44% / 没交"做成同一件事的推广，
而不是新机制。裸 0/1/2 印给学生是文案事故，不是判分。

**分值重排**：手上功夫四条 25→15（共 60），数据处理两条各 20（共 40）。
两份细则版本 `2026.10` → `2026.10.1`；记录里本来就存 `rubricVersion`，老记录不会被新分值重新解释。

**破例要说清**："拿不到事实就不扣分"是细则层一直守着的（宁漏不误）。但填空没交**必须**扣分，
否则学生不填也能拿 100，#61 等于白做。所以例外不写进判分引擎，而是由 runner 在
"这道题出得来"的前提下显式写 `Outcome=2`；数据不足时什么都不写。
**"没交"扣分、"这题没出"不扣 —— 两件事，两条路径。**

## 8. UI

在"读数面板"之后、"交卷评分"之前插入一节 **「要交的结论」**，按 `meta.tasks` 声明顺序渲染：
任务文本（prompt 全文）+ 它挂的填空行。一条任务可以挂 0 个或多个填空（纯开放题只渲染文字）。

- 填空行：`label` + 数字输入框 + `unit` 后缀。`TextInput.type` 为 `Number`；学生不填单位，
  填了单位说明没分清量与数。
- 值存页面 `@State answerValues: number[]`，**与 `meta.submissions` 同序**（这条不变量由断言守），
  同时调 `runner.setAnswer()`。
  **输入时不回显任何对错**（决定 3），框旁不放勾叉、不放应有值。
- 沿用 `Layout`/`Theme` 令牌；这是全工程第一个 `TextInput`，深浅色两套调色板都要非空
  （源码守卫那条断言管得到）。
- 填空与读数在同一条可滚列里 —— 设备探针按既有纪律：读哪格就单独滚到那格，不复用坐标。
- 填空的 `label` 与任务文本一起进 `check.mjs` 的 visible 文案清单（半角标点 + 内部词黑名单）。

## 9. 验收与测试

**离线（`tools/physics-check/check.mjs`，新增一节 L3 示踪弹 9）**

1. procedure 纯函数逐条断言：correct 值、每个指纹值、边界（n<4 → NaN）。
2. **负对照两条**：任意两个指纹之间至少差 20%；每个指纹与 correct 也至少差 20%。
   少了这两条，某条纸带上 F1 与 F3 恰好撞在一起时，判词会指着学生说他犯了个没犯的错。
   §5/§6 表里那组数最小间距是 33–40%，但那是**挑过的纸带**，不能拿挑过的数当保证 ——
   断言要跑在多条纸带（不同倾角/不同计数间隔/不同释放格数）上。
3. 判分链：认真做+填对 → 100；填成 F1 → 只扣这一条且判词点名"只吃首尾"；不填 → 扣这一条且判词说"没交"；
   数据不足 → 两条都不响，仍可达 100。
4. 文案：任务 prompt 与填空 label 过半角/黑名单闸门。
5. 会计：细则总分校验、`Rubrics.SOURCES` 索引、FactLabels 覆盖每个新事实键。

**变异（每条都要红）**：`relErr` 恒置 0（永远算对）；匹配顺序改成先比指纹；
"这题没出"时也写 `Outcome=2`；去掉枚举标签表（判词里露出裸 0/1）。

**设备探针（`tools/device/check-answer.mjs`）**：`inputText` 打进框 → 交卷判词点名错法；
填错值之后**屏幕上没有任何对错提示**（这条要能抓住"顺手加了即时反馈"的改动）；
任务文本第一次在屏幕上可见；历史回看里能看到他当年填的数（`ans.*` 落盘）。

## 10. 明确不做

- 自由文本判分（关键词判"有没有说出理由"）—— 与"宁漏不误"冲突，且需要另一套词表治理。
- 原始数据录入表格（让他把六段位移逐段敲进来）—— 原始读数是应用给的，收上来只能判抄没抄对。
- 沙箱端的成绩上报、账号、多次尝试取最高分。
- 其余五条场景的填空：通道打通后按 §5/§6 的形状复制，不在本批。

## 11. 风险

- **判"处理"仍要靠"数据是他自己的"这个前提。** 应用给的读数是准的，所以 correct 值是确定的；
  判的是"他会不会做这一步处理"，不是"他量得准不准"。这是刻意的，但意味着一个抄了别人纸带的人
  只要自己算一遍就能满分 —— 判分能到的边界就在这里，不假装它能看穿。
- **第一个 `TextInput`**：键盘弹起会压缩可视区，滚动位置与 `scrollToTop` 指纹可能互相影响；
  探针要先确认这一点再写断言，不要把布局问题误报成判分问题。
- **枚举标签表是新形状**：它一旦被用来印别的码（比如将来 sr-006 的错法），就要防它变成
  第二个"细则里写文案"的入口。约束：只允许 `Outcome`/`WrongKind` 这类**结果码**用，
  判据标题与证据模板仍在细则里。
